## Workflow and constraints
Define the desired mode: push-to-talk dictation, streaming transcription, voice conversation or TTS playback. Do not conflate an installed speech library with a working end-to-end voice mode. Map microphone permission, capture format, transport, provider/local engine, partial/final transcript, cancellation and insertion into the canonical user turn.

Inspect the current dictation package before adding a second media pipeline. Verify supported codecs, sample rates, language behavior and actual provider API/version from primary sources. Local models must be assessed on available hardware and measured latency; do not claim real-time behavior from marketing or desktop benchmarks on another machine.

Request microphone permission after user intent. Stop and release capture on cancel, navigation, disable and error. Keep interim transcript state separate from committed canonical input, and prevent duplicate final submission. An interim transcript may be shown in the draft — a draft is not a canonical turn — but only as a span the run *rewrites*, never as appended text: a cumulative update that appends duplicates re-punctuated words, and a run that ignores an outside change to the draft resurrects a just-sent message. Preserve audio privacy, retention policy, secret handling and explicit fallback choices. Do not silently upload recordings to another provider.

Test denied permission, unplugged device, silence, noisy/long speech, partial network loss, finalization races and mobile foreground recovery. Measure capture-to-first-partial and finalization separately. Read accessibility and keyboard behavior as part of composer integration. A simulated text response is not speech recognition evidence; mark provider, language and device checks that were not run.

## Current voice surfaces
- **Dictation** (`packages/dictation`): the composer mic streams a run-scoped span into the draft. Browser recognition prefers the on-device recognizer when `SpeechRecognition.available({processLocally:true})` reports it, applies English spoken punctuation (`applySpokenPunctuation`), stops on Escape, supports mouse/pen hold-to-talk, and is toggled by the `voice.dictate` palette command / `dictate` shortcut.
- **Read aloud and voice output**: `widgets/speechOutput.ts` is the one TTS queue — sentence chunks from `createSpeakableStream`, best browser voice via `pickVoice`, server clips prefetched one ahead with automatic fallback to the browser voice. Three read-aloud engines: browser voices, **built-in voices** (`src/localVoiceCatalog.ts` pins each Piper/Kokoro archive by size + SHA-256; `src/localTts.ts` runs them in a sherpa child process; `/api/tts/local` returns WAV) and a server voice (`/api/tts/speak`; `src/ttsCatalog.ts` lists the services — OpenAI-compatible URL, OpenAI, ElevenLabs, Google Cloud, Amazon Polly, Gradium — and `src/ttsProviders.ts` calls each at its fixed endpoint with the key typed in Settings → Voice (write-only, `data/voice-secrets.json`, per-service slot so another service never receives it) or an env-referenced key; only the OpenAI-compatible service takes a base URL, so a key never goes to a user-typed host). `/api/tts/speak` stays local-only for paired devices (a paid server); built-in voice listing/synthesis is paired-safe, install/remove is not (pinned by `remoteAccess.test.ts`, which also runs the server's policy validator). Only list a voice after synthesizing it and transcribing it back: a "text"-phoneme Piper voice and two Chinese voices fail in this runtime, Kokoro has no Japanese, and Kokoro runs slower than real time on the 4-core ARM host (≈1.2–2×), so the UI reports the measured factor.
- **Recognition routing on paired devices**: `/api/settings/voice` is not exposed to paired devices (it names endpoints and key variables). The paired-safe `/api/dictation/capability` carries the server's `selection` (provider, transport, language, policy), and both the mic and voice mode use it before falling back to local prefs — a phone must never guess the engine from its own defaults.
- **Voice mode** (`packages/voice-mode`): hands-free turns, pinned to the conversation it started in (a New chat is pinned by its first message) and running in one browser tab at a time (`widgets/tabClaim.ts`, BroadcastChannel; starting it elsewhere ends it here). The microphone stays open while the agent works; only the agent's own spoken reply closes it (talking over it interrupts) and it reopens when speech pauses for tool work. An utterance while the conversation is idle and on screen streams into the composer through `host.conversation.dictate` and is sent through `host.conversation.submitDraft` (the composer's own Send path); one while the agent works, or while another chat is open, goes straight to the pinned conversation through `host.conversation.send` with `queue` delivery — never the composer, whose sends dismiss pending permission/question requests. Spoken commands (`src/commands.ts`: stop, send now, send, cancel; configurable phrases, English + UI/recognition language defaults; only send/send now/cancel may end a longer utterance) act after a short settle instead of being sent: stop aborts the turn, "send now" alone merges the plain head of the queue into one interrupting turn (`widgets/sessionActions.ts`). `feedback: "silent"` is a control-only mode: no spoken replies, no earcons, no speaker claim. Replies (spoken/silent) is switched in the voice window itself (`RepliesSwitch` in the dock and the immersive layer), not in Settings; like every voice-mode pref it syncs as the `package.voice-mode` account preference, so the next conversation on any device starts with the last choice. A change mid-conversation (here, another tab or device) goes through `controller.applyFeedback()`: silent drops the reply being spoken and reopens the microphone, spoken reclaims the speaker and voices from the next turn. Narration while the agent works is opt-in and off by default (`thoughts`: off/brief/full, `actions`, `narrationCadence`: key/every): `src/narration.ts` turns streamed `assistant/reasoning-chunk` and `tool/call`/`tool/started`/`tool/error` into asides (localized phrases in `src/narrationPhrases.ts`, spoken in the voice's language; tool kinds come from `host.execution.describe`, with a plain tool-use fallback on older hosts). Key moments group a ~3 s window and keep ~12 s between remarks; failures are said at once; reasoning that arrives only with the final message is never read. Asides go through `SpeechOutput.enqueue(text, { kind: "aside", expiresAt })`: the reply and the user's speech drop any still waiting (`dropAsides`), only the newest one waits, one older than ~6 s is skipped, the microphone closes for them like for the reply, and talking over one silences it without dropping the turn's reply. Silent replies speak no asides, but the status line still shows the step in words (`snapshot.action`). `narrator: "model"` words grouped steps and brief thoughts with the account's small model through `POST /api/voice-mode/narrate` (`src/narrateRoutes.ts`): the client sends only a seq range of the pinned session, the server checks the session against `rc.space` (a foreign-Space id answers like a missing one) and reads the slice itself, and the model gets a digest — tool name, one scrubbed key argument, ok/failed, or reasoning text — never tool output. Only the account small model (`host.smallModel`) with `requireDirect: true` answers; none configured is `503 no-small-model` and the conversation keeps to phrases silently (never the session's own model). Limits: one call in flight and ≥4 s apart per conversation, 20/min per person across devices (`429`, the phrase is said instead), a 60 s cache per slice, 6 s model timeout. Two failures in a row keep the rest of the conversation to phrases with one on-screen notice; failed steps and full thoughts never wait for the model; a remark is never written to history. `GET /api/voice-mode/narration` (`{ configured, label }`) feeds Settings, whose "Set up" opens Settings → Sessions → Small model (`sessions.small-model`). Both routes are open to paired phones with `dictation.use` (`VOICE_MODE_REMOTE_ACCESS`); the rest of `/api/voice-mode` stays default-deny. `parseVoiceModePrefs` carries keys it does not know, so an older client's save keeps a newer client's settings. Recognition failures fall back across routes, then retry with backoff (a denied microphone waits for a tap or the page becoming visible); a refused send is a notice, never the end of the conversation. Its layer is hosted in `session.composer.before` and, as a lower-priority fallback, `composer.pending` — New chat has no area above the composer, and a running conversation must never be invisible. Every screen opens the compact dock above the composer by default (`presentation: "compact"`; full screen is an explicit preference or the dock's expand button for one conversation; a stored retired `"auto"` reads as compact). The immersive layer covers the chat column, not the whole shell: `VoiceModeHost` measures the `.workspace` box inside `.app-shell` and publishes it as `--voice-layer-block/inline-start/end` insets, plus the column's viewport top as `--voice-layer-viewport-top` (its head pads `max(space-3, --safe-top − that)`, so on phones, where the column starts under the floating header at the physical top, it clears the status bar and Dynamic Island), so the left navigator and the right rail stay visible beside it (and stay reachable — the layer is not modal and does not trap Tab). Only outside a shell does it fall back to a fixed full-viewport box.
- Packages are separate bundles: microphone and speaker ownership is coordinated only through the `MICROPHONE_CLAIM_EVENT` / `SPEECH_CLAIM_EVENT` window events, and voice mode imports dictation code only via `@polyth/dictation` (browser) and `@polyth/dictation/voice-runtime`.

## Verification and handoff
Suggested test locations (confirm current files first): `packages/dictation/test/speech.test.ts`, `speechOutput.test.ts`, `micControls.test.ts`, `packages/voice-mode/test/controller.test.ts` and `web.test.ts`. Happy-dom fakes prove wiring, not recognition quality: microphone, browser voices, on-device packs and device audio routing still need a real browser/device check.

Apply `docs/agents/verification.md` for the actual risk. Report changed paths, behavior verified, exact checks, and unknowns. Source inspection, unit tests, live execution and device evidence are separate. Do not load all other skills or rerun unchanged expensive checks without a causal reason.
