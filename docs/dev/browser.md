# Browser

`@polyth/browser` owns the controlled Chromium service, policy, package tool and workspace surface. Manual persistent Chat Workspace profiles remain a separate use of the same package's driver infrastructure; agent APIs cannot control those tabs.

`polyth_browser` projects through the generic `polyth-agent-tools` contribution for every shipped local harness: Claude, Codex, OpenCode, ACP profiles, Antigravity, Command Code and Pi. MCP-capable harnesses use the scoped MCP bridge; Command Code and Pi use private generated adapters backed by an inherited FD relay. Antigravity's native CLI only reads MCP servers from its global Gemini config, so Polyth launches it with a private per-runtime `HOME` whose `~/.gemini/config/mcp_config.json` carries the bridge while the real app data and home stay linked.

SSH-bound OpenCode receives the same package tools through an HTTP MCP endpoint carried by an SSH reverse forward. The remote listener and its local target are loopback addresses, and the HTTP route rejects non-loopback ingress; the ordinary scoped bearer and Polyth permission checks still apply. Polyth sends the private OpenCode launch config over SSH stdin; the bearer does not enter command arguments or a remote config file. A previously owned remote serve is replaced only after exact process-identity verification because it cannot prove possession of the newly minted grant. Other remote runtime families remain unsupported until their provider owns an equivalent private transport. Native subagents using a shared grant use its canonical owner; distinct Polyth canonical sessions have distinct contexts. Project-scoped grants resolve only when one active canonical owner matches Space, project, harness and working directory.

Before authorization, the generic bridge persists `package-tool/requested`. The Browser package listens through the web SDK and shows compact activity for the active session. Background is the default visibility preference; Auto-show reveals the existing workspace surface when requested. Browser agent-tool authorization is auto-approved by default through a Space-scoped package setting (`Settings → Browser → Auto-approve agent browser tool`). When that setting is off, the standard package-tool permission flow provides once/session/project decisions. Permission deny rules still win; origin approvals and navigation policy are unchanged. Disconnects expire pending approvals; execution rechecks the grant, contribution instance/revision and active session after the decision. The browser tool then creates or adopts only its canonical session's context and executes independently of viewer presence. Opening Browser subscribes to that same context without restarting or navigating it. No chat message is synthesized for takeover/resume.

User and agent share the same page, DOM, cookies and navigation history. Actions serialize in BrowserService. Take control advances a pause generation so queued agent work cannot run after a pause/resume cycle. Work already executing may finish; timeout alone does not release its queue slot. Returning control preserves user-created page state.

The local control MCP (`@polyth/mcp`) exposes the same HTTP routes as `browser.*` control actions: capability, session list/get/open/close, navigate, action, observe, console, context, and a read-only approvals listing. They always send the `agent` actor, so a user's Take control pause and origin policy still refuse them. Approving an origin, pausing or resuming control and changing agent auto-approval stay user decisions in the UI rather than MCP actions; `api.request` remains the raw escape hatch under the same policy.

Live CDP JPEG frames use the existing browser WebSocket channel and pacing helper. Chromium frames are acknowledged promptly; the service and each socket retain only the newest frame. Hidden viewers stop streaming; visibility is aggregated across authorized clients. Action targets are transient UI geometry. Package tool schemas mark typed values write-only so canonical native tool events redact them before persistence. Routine durable `browser/action-requested`, `browser/action-completed`, `browser/action-failed` and `browser/observation` events contain redacted metadata, not typed values, DOM snapshots or pixels. Explicit context captures retain their existing attachment path.

HTTP and WebSocket access validate project/session Space ownership. Origin approvals belong to one controlled browser session. Public HTTP(S) navigation is allowed after package-tool authorization. On a local-trusted deployment, Browser may reach the registering Polyth server's exact login origin only while UI authentication is required and the localhost bypass is off; this is a reachability exception, not authentication or Space authority. Hosted deployments, auth-off installs and localhost-optional auth receive no private self-origin exception because server-loopback traffic could otherwise inherit or probe authority it was not granted. Other loopback ports and private networks remain blocked unless that exact origin is separately allowlisted. If the page needs login or consent, the user opens that shared Browser context, chooses Take control, completes the step directly while agent control is paused instead of sending secrets through chat or `browser.type`, returns control, and tells the agent to continue. A page can expose entered data again after resume, so this is deliberate delegation of the ordinary authenticated UI context, not confinement to the tool grant's original Space. Unsafe schemes, URL credentials, downloads, service workers and ungranted browser permissions remain blocked. DNS lookup validation and Chromium's subsequent DNS resolution are separate: address pinning/rebinding resistance remains a limitation, not a proven guarantee. Do not describe the browser as a complete network sandbox.

Desktop builds stage the browser revision selected by locked `playwright-core` at build time; see [desktop architecture](desktop.md). Packaged startup performs no browser download. Development may use `POLYTH_CHROMIUM_PATH` or an installed browser. Chromium smoke tests are gated by `POLYTH_REAL_CHROMIUM=1`; fake/runtime tests are not desktop or device evidence.
