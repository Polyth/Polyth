# Browser

`@polyth/browser` owns the controlled Chromium service, policy, package tool and workspace surface. Manual persistent Chat Workspace profiles remain a separate use of the same package's driver infrastructure; agent APIs cannot control those tabs.

`polyth_browser` projects through the generic `polyth-agent-tools` MCP contribution for supported local Claude, Codex, OpenCode and ACP harnesses. The OpenCode-specific plugin/HTTP bridge is removed. Remote harnesses that cannot reach the local tool bridge remain unsupported. Native subagents using a shared grant use its canonical owner; distinct Polyth canonical sessions have distinct contexts. Project-scoped grants resolve only when one active canonical owner matches Space, project, harness and working directory.

Before authorization, the generic bridge persists `package-tool/requested`. The Browser package listens through the web SDK and shows compact activity for the active session. Background is the default visibility preference; Auto-show reveals the existing workspace surface when requested. The standard package-tool permission flow provides once/session/project decisions. Disconnects expire pending approvals; execution rechecks the grant, contribution instance/revision and active session after the decision. The browser tool then creates or adopts only its canonical session's context and executes independently of viewer presence. Opening Browser subscribes to that same context without restarting or navigating it. No chat message is synthesized for takeover/resume.

User and agent share the same page, DOM, cookies and navigation history. Actions serialize in BrowserService. Take control advances a pause generation so queued agent work cannot run after a pause/resume cycle. Work already executing may finish; timeout alone does not release its queue slot. Returning control preserves user-created page state.

Live CDP JPEG frames use the existing browser WebSocket channel and pacing helper. Chromium frames are acknowledged promptly; the service and each socket retain only the newest frame. Hidden viewers stop streaming; visibility is aggregated across authorized clients. Action targets are transient UI geometry. Package tool schemas mark typed values write-only so canonical native tool events redact them before persistence. Routine durable `browser/action-requested`, `browser/action-completed`, `browser/action-failed` and `browser/observation` events contain redacted metadata, not typed values, DOM snapshots or pixels. Explicit context captures retain their existing attachment path.

HTTP and WebSocket access validate project/session Space ownership. Origin approvals belong to one controlled browser session. Public HTTP(S) navigation is allowed after package-tool authorization. On a local-trusted deployment, Browser may reach the registering Polyth server's exact login origin only while UI authentication is required and the localhost bypass is off; this is a reachability exception, not authentication or Space authority. Hosted deployments, auth-off installs and localhost-optional auth keep self-origin blocked because server-loopback traffic could otherwise inherit or probe authority it was not granted. Other loopback ports and private networks still require an explicit origin approval. If the page needs login or consent, the user opens that shared Browser context, chooses Take control, completes the step without giving credentials to the model, then explicitly resumes the agent. That ordinary UI login delegates the authenticated context and is not confinement to the tool grant's original Space. Unsafe schemes, URL credentials, downloads, service workers and ungranted browser permissions remain blocked. DNS lookup validation and Chromium's subsequent DNS resolution are separate: address pinning/rebinding resistance remains a limitation, not a proven guarantee. Do not describe the browser as a complete network sandbox.

Desktop builds stage the browser revision selected by locked `playwright-core` at build time; see [desktop architecture](desktop.md). Packaged startup performs no browser download. Development may use `POLYTH_CHROMIUM_PATH` or an installed browser. Chromium smoke tests are gated by `POLYTH_REAL_CHROMIUM=1`; fake/runtime tests are not desktop or device evidence.
