# Browser

`@polyth/browser` owns the controlled Chromium service, policy, package tool and workspace surface. The package also exports a manual-only persistent-profile driver (`createProfileRegistry`, `browser.profiles` service); its tabs are registered as manual-only and agent APIs cannot control them. Its former in-repo consumer, Chat Workspace, now lives in the separate `polyth-chat-workspace` repository.

`polyth_browser` projects through the generic `polyth-agent-tools` contribution for every shipped local harness: Claude, Codex, OpenCode, ACP profiles, Antigravity, Command Code and Pi. MCP-capable harnesses use the scoped MCP bridge; Command Code and Pi use private generated adapters backed by an inherited FD relay. Antigravity's native CLI only reads MCP servers from its global Gemini config, so Polyth launches it with a private per-runtime `HOME` whose `~/.gemini/config/mcp_config.json` carries the bridge while the real app data and home stay linked.

SSH-bound OpenCode receives the same package tools through an HTTP MCP endpoint carried by an SSH reverse forward. The remote listener and its local target are loopback addresses, and the HTTP route rejects non-loopback ingress; the ordinary scoped bearer and Polyth permission checks still apply. Polyth sends the private OpenCode launch config over SSH stdin; the bearer does not enter command arguments or a remote config file. A previously owned remote serve is replaced only after exact process-identity verification because it cannot prove possession of the newly minted grant. Other remote runtime families remain unsupported until their provider owns an equivalent private transport. Native subagents using a shared grant use its canonical owner; distinct Polyth canonical sessions have distinct contexts. When an MCP harness supplies OpenCode's request-scoped `_meta.sessionID`, the bridge uses it only as an opaque correlation hint and still requires the exact live Space, project, harness, checkout and native-session match; project-scoped calls without that hint resolve only when one active canonical owner remains.

Before authorization, the generic bridge persists `package-tool/requested`. The Browser package listens through the web SDK only to optionally reveal its workspace surface; it contributes no session-header status indicator. Background is the default visibility preference; Auto-show reveals the existing workspace surface when requested. Browser agent-tool authorization is auto-approved by default through a Space-scoped package setting (`Settings → Browser → Auto-approve agent browser tool`). When that setting is off, the standard package-tool permission flow provides once/session/project decisions. Permission deny rules still win; origin approvals and navigation policy are unchanged. Disconnects expire pending approvals; execution rechecks the grant, contribution instance/revision and active session after the decision. The browser tool then creates or adopts only its canonical session's tabs and executes independently of viewer presence. `browser.open` reuses the first own tab by default; `parameters.newTab=true` creates another, and `parameters.browserSessionId` targets an existing own tab for any action. A tab ID from another project or canonical session returns not-found before navigation or interaction. Opening Browser subscribes to the selected own tab without restarting or navigating it. No chat message is synthesized for takeover/resume.

The Browser surface follows the active canonical session by default and shows only its tabs. A fresh unsaved chat sees only that project's unlinked tabs; it never adopts another agent's browser. The selected tab is a device-local preference keyed by connection, account, Space, project and canonical session. Switching account, Space, tab, project or session unmounts the old viewer, closes its frame subscription and discards its unconfirmed capture. Late reads, navigation responses and captures cannot replace the new viewer or attach to a different draft. The tab list and the credential-fill approval card refresh on the chat's browser session events (`browser/action-*`, `browser/vault-fill-*`) rather than on short timers, with a 15 s resync as a safety net; only the selected visible tab streams frames. A `navigation` event updates the stored tab URL/title before `goto()` settles, and its URL wins over a slower re-read. The default service budget is 16 contexts across the shared host service and four tabs per canonical session/project lane; in-flight opens reserve capacity before asynchronous driver launch and release it on failure. No live tab is evicted to make room.

Within one tab, user and agent share the same page, DOM, cookies and navigation history. Every tab has an isolated Chromium context; cookies and storage do not cross tab/session boundaries. Actions serialize in BrowserService. Take control advances a pause generation so queued agent work cannot run after a pause/resume cycle. Work already executing may finish; timeout alone does not release its queue slot. Returning control preserves user-created page state.

The local control MCP (`@polyth/mcp`) exposes the same HTTP routes as `browser.*` control actions: capability, session list/get/open/close, navigate, action, observe, console, context, and a read-only approvals listing. They always send the `agent` actor, so a user's Take control pause and origin policy still refuse them. Approving an origin, pausing or resuming control and changing agent auto-approval stay user decisions in the UI rather than MCP actions; `api.request` remains the raw escape hatch under the same policy.

Live CDP JPEG frames use the existing browser WebSocket channel and pacing helper. Chromium frames are acknowledged promptly; the service and each socket retain only the newest frame. Hidden viewers stop streaming; visibility is aggregated across authorized clients. Action targets are transient UI geometry. Package tool schemas mark typed values write-only so canonical native tool events redact them before persistence. Routine durable `browser/action-requested`, `browser/action-completed`, `browser/action-failed` and `browser/observation` events contain redacted metadata, not typed values, DOM snapshots or pixels. Explicit context captures retain their existing attachment path.

The Add context menu offers an element point, area, text range or whole page. A point selects an element without clicking it; dragging selects an area, while Select text quotes the DOM range in either direction. Selections use the displayed frame revision and viewport coordinates and reject stale/outside geometry. While selecting and reviewing, the viewer pauses streaming and responsive page resizing so the point or region stays aligned with its captured frame. Capture shows a compact review card with the site, readable element/text label, image when available, coordinates, expandable page/selector details and an optional note. Add to message puts the structured capture in that session's composer draft; it does not send a message. Discard or leaving the tab deletes unconfirmed draft artifacts. Frames do not install a new ResizeObserver on every image update.

`BrowserContext.point` is the optional exact selected viewport point; `BrowserContextElementSummary.documentBounds` adds document coordinates including the scroll offset. Old records without these fields remain readable. Element, area and text captures retain bounded selectors, accessible names, viewport bounds and visible text; region elements use the same unique selector generation as point hits. The shared model formatter includes tab ID, capture time, viewport, point, selectors and geometry so an agent can locate the recorded selection. Attachment sanitization and prompt-history recall preserve these optional fields. Text images remain opt-in through `includeScreenshot`; the surface enables them for a text selection. The capture pipeline redacts URLs and metadata, and the existing sensitive-content policy keeps captures text-only after protected input.

HTTP and WebSocket access validate project/session Space ownership. Origin approvals belong to one controlled browser session. Public HTTP(S) navigation is allowed after package-tool authorization. On a local-trusted deployment, the in-app Browser is local-first and may reach loopback/private development origins; its exact login-origin seam still applies only while UI authentication is required and the localhost bypass is off, and is a reachability exception rather than authentication or Space authority. Hosted deployments, auth-off installs and localhost-optional auth receive no private self-origin exception because server-loopback traffic could otherwise inherit or probe authority it was not granted; non-local-trusted Browser remains explicit-only and requires a separately allowlisted private origin. If the page needs login or consent, the user opens that shared Browser context, chooses Take control, completes the step directly while agent control is paused instead of sending secrets through chat or `browser.type`, returns control, and tells the agent to continue. A page can expose entered data again after resume, so this is deliberate delegation of the ordinary authenticated UI context, not confinement to the tool grant's original Space. Unsafe schemes, URL credentials, downloads, service workers and ungranted browser permissions remain blocked. DNS lookup validation and Chromium's subsequent DNS resolution are separate: address pinning/rebinding resistance remains a limitation, not a proven guarantee. Do not describe the browser as a complete network sandbox.

Messages with http(s) links get an "Open links in Browser" action (`session.message.actions`): it reuses the chat's live Browser tab or creates one for that session, lists GitHub/GitLab/Bitbucket PR/MR links first, and navigates through the same user navigation route as the address bar, so policy and origin approval still apply; credentialed and non-http(s) URLs never open. The More menu has a plain-text Reader view built from the server's already-redacted page observation. Details: [`packages/browser/README.md`](../../packages/browser/README.md).

Desktop builds stage the browser revision selected by locked `playwright-core` at build time; see [desktop architecture](desktop.md). Packaged startup performs no browser download. Development may use `POLYTH_CHROMIUM_PATH` or an installed browser. Chromium smoke tests are gated by `POLYTH_REAL_CHROMIUM=1`; fake/runtime tests are not desktop or device evidence.
