- Case: `UX-FIXTURE-BUILD`

- Verdict: **changes required**

## Blocking conformance findings

1. The isolated Polyth service was not launched with the command required by
   the specification. The `polyth-ux-fixture-58a2` tmux pane runs:

   ```text
   env HOME=/tmp/polyth-ux-fixture-home-58a2 ... PORT=4418 \
     node --experimental-strip-types \
     --import file:///tmp/polyth-ux-fixture-home-58a2/loopback-listen.mjs \
     packages/server/src/index.ts
   ```

   The specification requires `NODE_OPTIONS=--experimental-strip-types`,
   `PORT=4418`, and `npm start`. It does not authorize a preload. The preload
   safely forces host-less listeners onto `127.0.0.1`, and the resulting
   listener is loopback-only, but this remains an unapproved launch and file
   layout deviation. The current server calls `server.listen(port)` without a
   host, so the exact specified launch would bind a wildcard listener. The
   specification and current server behavior must be reconciled before the
   fixture can conform safely.

2. Runtime state exceeds the specification's exact final layout. In addition
   to the listed files, the isolated data directory contains
   `knowledge.db`, its WAL/SHM files, `model-visibility.json`,
   `schedule.json`, and `plugins/`; the isolated home contains
   `loopback-listen.mjs`. These are isolated and contain no observed user data,
   but the specification does not permit them in its exact layout. Either
   enumerate the current runtime's generated state and the safety preload in
   the specification, or rebuild so only the permitted state exists.
