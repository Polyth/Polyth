# Аудит агентної документації Polyth

Дата: 2026-09-09. Репозиторій: `otto-assistant/polyth`, гілка `master`.
Зафіксований commit: `d70f875ecb919a0a7d59488fc7ddafc47915b558`; його час у GitHub — 2026-09-08T17:05:42Z.

## Що перевірено

Через GitHub-конектор прочитано активні агентні правила, усі чотири Cursor-ролі, feature tutorial, root manifest, поточний CI та selector тестів, контракти server package host, приклади server/web registration, exports commands, частини Codex runtime, mobile bridge і повний Link interface та Link architecture. Переглянуто дерева кореня, пакетів, документації й мобільного застосунку. Точні SHA та **повне / часткове / лише дерево** покриття містяться в `evidence.json`.

Це цільовий аудит архітектурних меж і агентної інфраструктури, **не построкове рев’ю всіх функцій репозиторію**. Наявність шляху в навігаторі не означає, що весь його код перевірено. Повного checkout приватного репозиторію в середовищі підготовки не було; прикладні build/test, реальні провайдери, застосунки та нативні пристрої не запускалися. Перевірки самого комплекту наведені окремо в `VERIFICATION.uk.md`.

## Ключові проблеми попередніх інструкцій

Старий AGENTS заперечував існування CI, хоча workflow уже працює як конфігурація репозиторію. Він надмірно узагальнював exports та OpenCode-центричну модель проєкту. Старий multi-harness документ містить capability matrix, яка вже суперечить деклараціям Codex runtime. Tutorial містив неготовий route snippet та прив’язку до конкретного живого порту/інстансу. Cursor-ролі примусово фіксували модель і делегування. Legacy skill надто широко вимагав live-control MCP.

Ці суперечності не означають, що все їхнє оточення неправильне. Тому архітектурні інваріанти збережено, активні входи переписано, а спеціалізовані документи залишено з явним правилом звіряти конкретні API/готовність із поточним кодом. Приклади виправлень і джерела — `known-drift.md`.

## Що додано

27 тематичних скілів із точками входу, порядком роботи, обмеженнями й перевірками. Єдина AGENTS-політика; адаптери Cursor, Claude Code, Codex/OpenCode через спільні skills, Gemini та Copilot; ручний пакет контексту для звичайного ChatGPT. Окремі матриці ризику, мобільних сценаріїв, дизайну, безпеки й доказовості; шаблони задач, ADR, багів, перевірок і передачі роботи.

CLI будує актуальний manifest inventory, показує відповідні скіли й джерела, аналізує змінені шляхи та задекларованих залежних споживачів, знаходить дрейф хешів, перевіряє структуру знань і формує обмежений context bundle. Він **не виконує код із manifest, не читає довільні секрети, не ходить у мережу, не запускає Polyth і не змінює git**.

## Що навмисно не змінено

Жодного runtime-коду, npm/Cargo залежностей, lockfile, існуючого release workflow, signing, MCP-конфігурації чи дозволів. Додано окремий легкий workflow лише для агентних матеріалів і тестів інструмента. Не зроблено хибної «універсальної» копії 27 skills у кожній прихованій директорії; Claude має один рідний маршрутизатор, що читає спільні файли.

## Межі гарантій

Документація зменшує повторні пошуки та робить помилкові припущення помітнішими, але не може гарантувати відсутність галюцинацій або замінити причинні тести. Hash equality означає незмінність байтів, а не правильність твердження. Impact graph охоплює лише manifest-залежності й curated routes, не всі динамічні зв’язки. Відсутність тесту в generic CI не означає, що він не потрібен конкретній задачі.

Сумісність форматів звірена з офіційною документацією; фактичне завантаження в установлених у тебе версіях Cursor/Claude/Codex потребує короткого smoke-check. Native interface, локальне сповіщення та ticket parser не прирівнюються до готового парування, push або OS widgets.

## Подальший робочий цикл

Агент визначає власника задачі, читає один скіл і конкретний контракт/тест, перевіряє локальний дрейф, виконує зміну, запускає необхідні перевірки та оновлює тільки зачеплені знання. Повний скан репозиторію не є стандартним вступом; розширення аналізу потрібне при реальній невизначеності, зміні публічного контракту або провалі перевірки.
