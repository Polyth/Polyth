# Встановлення комплекту агентних знань

ZIP має **структуру від кореня репозиторію**, включно з прихованими директоріями. Додаткової верхньої папки немає. Він замінює 8 відомих файлів інструкцій, додає нові матеріали та інструменти, але не змінює runtime, залежності, існуючі CI/release-файли, MCP-конфігурацію чи дозволи. Повний список — `overlay-manifest.json`.

База аудиту: `d70f875ecb919a0a7d59488fc7ddafc47915b558`. Розпакування поверх новішої гілки без перевірки може затерти нові інструкції. На час застосування припини паралельне редагування цільових файлів іншими агентами.

## Рекомендований спосіб: перевірка перед записом

Потрібні Git і Python 3.10+. Окремо завантажений `install_polyth_agent_kit.py` — копія `scripts/agent-kit-install.py` з архіву. Підстав фактичні шляхи до архіву, установника та свого checkout.

```sh
python3 /path/to/install_polyth_agent_kit.py /path/to/polyth-agent-kit.zip /path/to/polyth
```

Це dry run: нічого не записує. Перевіряє ZIP, перелік дозволених файлів, контрольні суми, корінь Polyth, вихідні версії файлів, staged/unstaged конфлікти в цільових файлах та symlink-шляхи. Зміни в інших файлах не чіпає. Інший HEAD допускається лише з явним повідомленням і коли цільові оригінали все ще збігаються; це не означає, що весь новий код пройшов аудит.

Після перевірки списку:

```sh
python3 /path/to/install_polyth_agent_kit.py /path/to/polyth-agent-kit.zip /path/to/polyth --apply
```

Установник створює резервну копію поза репозиторієм і друкує її шлях. Власний новий/порожній каталог можна задати через `--backup-dir /path/to/backup`. Він не робить `git add`, commit, push, npm install, запуск застосунку чи міграції. Повторне застосування ідентичного архіву нічого не змінює.

При конфлікті немає небезпечного `--force`: переглянь локальні зміни й зведи інструкції вручну. При помилці запису виконується спроба відкату вже записаних файлів; виявлені паралельні правки не перезаписуються, а повідомляються для ручної перевірки. Це не транзакція файлової системи і не гарантія проти одночасного зловмисного редагування каталогів — не запускай інших writer-агентів під час встановлення.

## Звичайне розпакування

На перевіреній базі без змін у цільових інструкціях можна просто розпакувати ZIP **у корінь** Polyth, зберігаючи приховані директорії. Наприклад, у Unix:

```sh
cd /path/to/polyth
unzip -o /path/to/polyth-agent-kit.zip
```

Цей спосіб, на відміну від установника, **безумовно перезаписує** наявні файли. Не використовуй його як обхід конфліктів. Архів не містить команд автоматичного видалення старих файлів; застарілі активні entrypoints замінюються на нові правила або вузький redirect.

## Перевірка та коміт

```sh
node scripts/agent-kit.mjs check
node --experimental-strip-types --test scripts/test/agent-kit.test.ts
python3 scripts/test/agent_kit_install_test.py
node scripts/agent-kit.mjs doctor mobile

git status --short
git diff --stat
```

`check` перевіряє структуру комплекту в повному checkout; не запускає прикладні тести. `doctor` повідомляє про дрейф джерел, а не про автоматично доведені баги. На новішому master зміни хешів очікувані й потребують лише адресної перевірки відповідних тверджень. Структурний `--kit-only` призначений для самого overlay, не для підміни перевірки репозиторію.

Переглянь і додай у коміт **лише файли комплекту**, перелічені в manifest, та сам manifest. `git diff --stat` не показує ще не додані нові файли — тому також потрібен `git status`. Не роби сліпий `git add .`, коли паралельно є інша робота. Приклад назви коміту: `docs(agents): add shared skills, evidence routing and safe tooling`.

## Відкат і перший запуск агентів

Після окремого коміту комплект можна відкотити звичайним `git revert` саме цього коміту, врахувавши подальші зміни. До коміту оригінали лежать у надрукованому backup-каталозі; `backup-manifest.json` містить список нових файлів і встановлені SHA-256. Відновлюй/видаляй лише відповідні файли після перевірки, що їх не змінили пізніше. Не застосовуй `reset --hard` або `clean` до всього репо.

Запусти нову сесію агента й перевір завантаження правил за `client-compatibility.md`. Cursor/Codex/OpenCode отримують спільні skills відповідно до підтримки клієнта; Claude має `/polyth-guide`; звичайний ChatGPT потребує явного контексту або доступу до файлів. Жоден із цих файлів не додає агенту нових інструментів чи прав.

Контрольні суми в ZIP виявляють пошкодження/невідповідність, але не є цифровим підписом автора. Для перевірки перед завантаженням використай також окремо надану SHA-256 архіву.
