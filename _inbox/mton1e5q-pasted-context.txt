Потрібно вдосконалити mobile UI Polyth для відображення заповненості контекстного вікна агента так, щоб це було ненав’язливо, інформативно і не перевантажувало інтерфейс.

Ціль

Показувати використання context window навіть тоді, коли сесія вже idle, тобто коли нижній блок активності агента може бути прихований або менш помітний.
Також потрібно дуже делікатно показати стан/прогрес у нижньому блоці активності агента, але так, щоб це не читалося як “виконано X із Y тасок”.

1. Верхній індикатор контексту в хедері сесії

Замість звичного spinner перед назвою сесії треба зробити постійний context indicator.

Як має виглядати
Маленький orb / donut / pie indicator перед назвою сесії.
Він показує заповнення контексту.
Наприклад: 63% = заповнене коло/кільце на 63%.
Стиль: дуже легкий, витончений, у frozen glass / Apple-like стилі.
Має виглядати як властивість сесії, а не як loading spinner.
Поведінка
Idle: індикатор статичний.
Agent working: сам індикатор не має перетворюватися на агресивний loader.
Якщо потрібно показати активність — лише дуже ніжна secondary-анімація:
ледь помітний pulse,
або маленька orbit-dot,
або делікатне breathing glow.
Тобто:
форма/заповнення = context usage
дуже легка анімація = session is active
Tooltip / details

При tap / hover / long press по індикатору показувати компактний popover:

Контекст · 63%
128k / 202k tokens

Опційно можна додати:

Last compacted 18m ago
Важливо
Не робити це схожим на spinner.
Не робити це схожим на task progress.
Не додавати зайвого тексту в сам хедер.
Індикатор має бути помітним, але не кричущим.
2. Нижній блок активності агента

У картці активного агента (GPT-5.6 Sol ...) потрібно дуже ніжно показати стан/прогрес.

Ключова проблема

Раніше горизонтальний progress bar міг сприйматись як:

“3 з 5 тасок виконано”
або як workflow/task completion progress

Цього треба уникнути.

Як зробити правильно

Дозволяється використати дуже слабкий, майже атмосферний індикатор, але не класичний explicit progress bar.

Підійдуть такі варіанти:

дуже тонкий inner glow / underglow вздовж нижнього краю картки;
ледь помітний hairline accent, який не виглядає як шкала завершення;
subtle moving shimmer / soft fill, який більше схожий на “activity presence”, ніж на “progress completed”.
Візуальні правила
Ніяких товстих барів.
Ніяких контрастних заповнених шкал.
Ніяких явних “63%” всередині цього нижнього блоку.
Це лише м’яка підказка, що агент активний / щось відбувається.
Семантично це має читатися як live activity ambiance, а не як завершення задач.
3. Альтернативний режим у налаштуваннях

Додати опцію в налаштуваннях для способу відображення context indicator:

Option A — default

Logo tint mode

Лого моделі / агента з легким tint залежно від usage context.
Наприклад:
низьке використання → нейтральний тон
вище → трохи насиченіший
критично → warning tint
Option B

Pie / donut mode

Замість логотипу — компактний pie/donut indicator, який напряму показує відсоток контексту.
Для settings UI

Додати невеликий selector:

Лого з тінтом
Режим кола
4. Стиль та дизайн-система

Обов’язково:

дотримуватися поточних стилів Polyth;
перевикористовувати існуючі компоненти, токени, radius, spacing, glass-ефекти;
не винаходити окрему мову стилів для цього елемента;
не городити зайвий CSS;
мінімізувати новий код;
усе повинно природно вбудуватися в існуючий mobile UI.
Візуальні принципи
premium
light
glass / frosted
unobtrusive
elegant
readable
Apple-like restraint
5. Семантика кольорів

Використовувати існуючі semantic tokens, а не хардкодити кольори.

Рекомендована логіка:

0–70% → neutral / calm
70–90% → slightly more visible
90%+ → warning
critical → stronger warning/accent, але без агресії
6. Що саме треба зробити
Оновити header session chip:
замінити spinner на context orb / donut.
Додати popover з деталями контексту.
У нижньому agent activity card:
додати very subtle live-progress treatment, який не читається як task completion bar.
Додати settings option для перемикання:
Logo tint mode
Pie/donut mode
Забезпечити коректний вигляд у:
active session
idle session
high context usage
compact / narrow mobile width
7. Acceptance criteria

Результат вважається вдалим, якщо:

контекст видно навіть коли сесія idle;
індикатор не плутається зі spinner;
нижній індикатор не сприймається як “X із Y задач виконано”;
UI не став важчим;
рішення виглядає природною частиною Polyth;
зміни реалізовані компактно, акуратно і з повторним використанням наявної стилістики.
